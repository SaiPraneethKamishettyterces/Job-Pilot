The big idea

JobPilot decouples job discovery from per-user matching. A scheduled, user-agnostic global ingestor keeps one shared JobPosting pool fresh. When a user runs, a cheap two-stage matcher (vector ANN → LLM rerank) pulls the best jobs from that pool, materializes them as the user's own Job/JobMatch rows, then prepares full application packages — but never submits; the human approves. Everything (incl. generated DOCX/PDF bytes) lives in one Postgres.

Data flow — end to end

0
demand-profile.ts · scheduled

Demand profile

Aggregates active subscribers' target roles (→ steer keyword search APIs) and target companies (→ expand the ATS board set). One profile drives the whole cycle.

1
global-ingestor.ts → GlobalIngestRun

Global ingest (user-agnostic, daily)

Fans out across three source classes, bounded-concurrency, fail-soft per source:

ATS registry: greenhouse · lever · ashby · recruitee … free aggregators: remotive · remoteok · arbeitnow · themuse · adzuna · usajobs apify (paid, gated by token)

Registry is rotated least-recently-checked-first & self-heals via per-board health (auto-deactivate dead slugs).

2
job-normalizer.ts · job-posting-repository.ts

Normalize → dedupe → upsert pool

Each raw posting is normalized to a common shape and collapsed on a global dedupeKey, then upserted into the shared JobPosting pool (insert vs update tracked).

3
embed-postings.ts · pgvector

Embed new/changed postings

Pending rows get a vector(768) embedding (OpenAI-compatible embed model) indexed by HNSW for cosine ANN. Stale postings past POOL_RETENTION_DAYS are soft-expired so matching sees only fresh, live jobs.

currently ~1,000 embedded/run — full-pool backfill is a next step
4
runs.ts POST /start → application-pipeline.ts · stage A

Per-user run → candidate generation (cheap, no LLM)

On manual run or daily scheduler: build a profile snapshot, then retrieve ~200 candidates from the pool. Vector ANN when AI configured; keyword+recency fallback otherwise (always returns jobs). Hard filters applied here: blocked companies, remote/location, min salary, visa sponsorship, exclude already-applied.

5
rerank.ts · stage B → Job + JobMatch

Rerank & materialize per-user rows

Deterministic feature score (0.6·vector + 0.25·title + 0.15·skill) ranks all candidates; top 40 get LLM rerank (Gemini Flash) — or a deterministic verdict with no AI key. Each result is written as a per-user Job (linked to the pool posting) + scored JobMatch.

6
select-matches.ts

Shortlist (cap + diversity)

Cap = min(plan/day, personal cap, monthly remaining). Caps any one employer to ~⅓ of the day's slots, fills the rest by next-best score.

7
application-generator.ts → Application + ApplicationDocument + Artifact

Prepare application packages

For each shortlisted job: create an Application, then AI-generate tailored resume, cover letter, cold email, and autofill package. Files stored as BYTEA in the Artifact table (no object store), downloaded via authenticated /api/files.

status → NEEDS_APPROVAL / ASSISTED_REQUIRED
8
AUTO_SUBMIT=false · notifications/email-service.ts

Human approves — then submit

Pipeline stops at "prepared". Nothing is auto-submitted under current config; the user reviews in the UI and submits. A completion email is sent (log transport in dev). Automation (Playwright form-filler) is the unfinished frontier.

Cross-cutting

AI routing

Tasks mapped to providers in model-config.ts: Anthropic Claude (cover letter / docs) + OpenAI-compatible endpoint for Gemini Flash/Pro + embeddings. Token usage tracked per call → AIUsageEvent.

Auth & tenancy

JWT bearer; every per-user query scoped by userId. Admin surface gated by require-admin + ADMIN_EMAILS.

Deploy

Cloud Run via Dockerfile + cloudbuild.yaml; secrets from Secret Manager; prod DB = Cloud SQL w/ pgvector. /health + /readiness probes.
